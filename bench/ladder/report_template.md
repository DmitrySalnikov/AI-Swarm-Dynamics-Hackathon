# Лестница семантической близости: отбор задач

Набор задач для проверки метода δ(t): ловит ли он разделение работы, а не просто разные темы. Четыре ступени по
10 задач — от далёких областей к одному шаблону. Все числа ниже получены кодом (`bench/ladder/report.py`) из файлов
прогонов и журналов расходов.

## 1. Итоговые наборы

Файлы: `bench/ladder/rung_1.jsonl` … `rung_4.jsonl` (формат задач `set_3`/`set_4`: id, set, domain, title,
source с лицензией, prompt, answer, check; плюс `gen` — генератор, параметр и сид для воспроизведения).

{final}

## 2. Модель и условия

- cloud.ru Foundation Models, `deepseek-ai/DeepSeek-V4-Flash` (апрельская версия, не 0731), temperature 1.0,
  reasoning_effort high, max_tokens 60 000. Все прогоны отбора — на этой модели; с прогонами 0731 не смешивались.
- Длина решения = `usage.completion_tokens` (рассуждение + видимый ответ).
- cloud.ru не соблюдает max_tokens: прогонов длиннее 60 000 токенов — {over} (максимум {over_max}); из них закончились
  сами (`finish_reason=stop`) — {over_stop}. Такой прогон считается обрывом по длине и неверным ответом.
- Медианная скорость генерации — {tok_s} ток/с.

## 4. Генераторы и проверка ответов

- Каждый генератор: один параметр длины, фиксированные сиды (задача = генератор, значение, сид), эталон
  вычисляется кодом и пересчитывается вторым независимым способом. Самопроверка (`selftest.py`: эталон против
  независимого пересчёта через ту же `grade()`, отказ на испорченном ответе, воспроизводимость) — {selftest}.
- Проверка ответа — `embedding_eval/gen_runs.py: grade`. Добавлено: дроби в числовых ответах, допуск для списков,
  разбор числа после последнего «=»; старые типы проверки не изменились (сверено на 1 570 прежних ответах: 0 расхождений).
- Если в ответе нет строки `ANSWER:`, берётся последняя строка видимого ответа (флаг `--answer-fallback`):
  число таких прогонов — {no_answer}. Прогонов, закончившихся без видимого ответа (считаются неверными), — {empty_visible}.

## 6. Основной отбор (шаг 3)

Фильтры: медиана длины в [10 000; 25 000], CV = выборочное std / mean ≤ 0,25, неверных не больше 20 % прогонов
(5 прогонов — не больше 1). Пограничные (3/5 верных или CV в пределах ±0,05 от порога) — дополнительно до 8 прогонов.

Флаг заученности: средняя попарная косинусная схожесть решений одной задачи. Вектор решения — среднее
центрированных векторов окон (Qwen3-Embedding-4B через OpenRouter, окна 2048/1024, центрирование по всем окнам всех
кандидатов — схема `vectorize.py`). Флаг — выше медианы ступени + 3·MAD.

## 8. Что пошло не по плану

1. cloud.ru не ограничивает длину ответа (раздел 2), поэтому «обрыв» определён по числу токенов.
2. Обрывы сети и сон ноутбука: потоки зависали. Добавлен таймаут чтения 300 с; такие пары перезапускались.
3. Пачки датасетов: вместо 5–8 задач — 2–5, потому что одна задача TheoremQA уже даёт 5–18 тыс. токенов.
4. TheoremQA проверяется с допуском 4 % (так считает собственный код проверки TheoremQA; многие эталоны округлены
   до 2 значащих цифр), а не 1 %, как в `set_3`/`set_4`.
5. UGPhysics исключён: на калибровке верно 0–1 из 4 по каждой из 5 тем. Разбор показал спорные эталоны: катушка
   считается длинным соленоидом вопреки условию (эталон 39,5 мкГн, модель 17,65 с учётом конечной длины); NaCl —
   2a вместо 2·d₁₁₁; недоопределённое условие про глубину резкости лупы.
6. Шаблон ступени 4 — определитель 6×6 с элементами в [−4; 4]: при элементах в [−9; 9] длина 5×5 ≈ 12 тыс.,
   6×6 ≈ 32 тыс. Тот же генератор стоит на ступенях 1 и 3.
7. На ступени 2 после основного отбора прошло меньше 10 задач; добавлены новые экземпляры генераторов, которые
   промахнулись по длине при низком разбросе, с поправленным параметром (суффикс `_v2`).
8. У жордановой формы и минимального многочлена собственные значения даны в условии (иначе — корни многочлена
   8-й степени).
