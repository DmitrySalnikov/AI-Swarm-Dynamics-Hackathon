# Swarm pipeline prompts

Generated by `scripts/export_prompts.py` from the code; do not edit by hand.
There is one current prompt implementation, used automatically. Historical versions are preserved in Git.

## How an agent sees a turn

- **System message** (first message of the agent history): the line "You are Agent N …" plus the protocol text below.
- **User message** of every turn: a JSON snapshot with `agent`, `phase`, `team`, `current_task`, `own_answers`, `inbox` (team messages), and per phase: `tasks` + `available_tasks` (distribution, with the FULL problem texts), `task` (solving), `shared_packet` (commit); plus `instruction` (the per-phase text below).
- The agent answers with one JSON action; invalid actions get "Action rejected: … Follow the JSON action protocol."

## Swarm

**System message** (agent 1 of 3 in this export):
```
You are Agent 1 in a team of 3 agents. The team has the same number of problems; each agent solves exactly one.
You work in three steps. Reply with exactly one JSON object, nothing else.
1. Distribution. Pick the problem you will solve. DO NOT SOLVE ANY PROBLEM NOW. DON'T EVEN TRY.
   Each reply performs exactly one action. Follow the current request instruction.
   The coordinator requests your preference first and requests a claim in a later turn.
2. Solving. Solve your problem and return
   {"action":"submit","task_id":"<your problem id>","answer":"<final answer>","notes":"<short description of your solution, 2-3 sentences>"}.
   Your answer and the short description are sent to the team chat.
3. Final answers. You receive the team chat with every answer. Return
   {"action":"finish","answers":{"<problem id>":"<answer exactly as in the chat>", ...}}.

```

**Distribution: send preference instruction:**
```
Distribution step: announce your preference. DO NOT SOLVE ANY PROBLEM NOW. DON'T EVEN TRY. For this reply, return only {"action":"send","to":"all","message":"which problem you want, in one sentence"}. You will be asked to claim a problem in a later request.
```

**Distribution: claim task instruction:**
```
Distribution step: your preference message has been accepted. DO NOT SOLVE ANY PROBLEM NOW. DON'T EVEN TRY. For this reply, return only {"action":"claim","task_id":"<one ID from available_tasks>"}. If your preferred problem is no longer available, choose another available problem.
```

**Solving instruction:**
```
Solving step. Solve your problem. Return one submit action with the answer and a short description of your solution (2-3 sentences).
```

**Commit instruction:**
```
Final step. The team chat below has every answer. Return one finish action with all answers, copied exactly.
```

## Recovery messages

Added to the agent history after an interrupted provider call; the observed fragment follows where noted.

**Automatic continuation of an interrupted solving stream (`stable_live.py`), followed by the fragment:**
```
The last provider stream was interrupted. Its billing is unresolved and its request will not be replayed. Continue your current task from your own observed private working fragment below. Treat it as incomplete, check the arithmetic, and avoid repeating finished work unnecessarily. Return one valid JSON action.


```

**Explicit restart turn (`resume_parallel.py`), optionally followed by the fragment:**
```
The previous attempt was interrupted and may have been billed. Its outcome is unknown. This is an explicit recovery turn. Continue solving your current task from your retained completed notes and answers. No missing output has been fabricated. Return one JSON action.
```

**Distribution retry (`protocol_v2.py`):**
```
The previous distribution request was interrupted. Billing is unresolved. Continue distribution from your retained context and the currently available tasks. Do not solve yet.
```

**Commit retry (`protocol_v2.py`):**
```
The previous commit request was interrupted. Billing is unresolved. Retry the commit using the unchanged shared packet; preserve all published answers exactly.
```
